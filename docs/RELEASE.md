# 本人限定から、公開へ

## 段階

1. **本人限定(既定)。** 本人だけが使える。機能ができるまでは「準備中」、あるいは動作しない状態。使い込んで、直す。
2. **公開。** 不特定の人が使える状態にする。人間が、明示的に承認したときだけ。

「本人限定」を、どう実現するかは、スタックごとに違う(たとえば `web-worker` は Cloudflare Access)。`docs/STACK.md` を見る。

## 公開してよいかの確認(人間)

自動検査(`security`)の合格は、安全の保証ではない。次を、人間が確認する。

- [ ] 認証・認可: 利用者ごとにデータが分かれている。他人のデータを、読み書きできない。
- [ ] 秘密の値は、保管先(Secrets)にあり、配布物・ログ・Git のどこにもない。
- [ ] 外部サービスの利用上限(費用、回数)を設定した。濫用への対策(レート制限など)がある。
- [ ] ログに、本文・トークン・個人情報を出していない。
- [ ] バックアップと復元の手順を試した(データを持つ場合)。
- [ ] 実機で、主要な操作を確認した(スマホで使うものは、スマホで)。
- [ ] 本番の設定(オリジン、ヘッダー、権限)が、実際の挙動で有効。
- [ ] 依存パッケージのライセンスを確認した。

## まだないもの

次の機械的な強制は、まだこのテンプレートにない。公開の切り替えは、人間が手で行う。

- 「承認済みのコミット、本人のマージ、最新の CI の成功」をすべて満たしたときだけ配備を許す、リリースゲート。([hitomazu](https://github.com/kuroneko913/hitomazu) の `scripts/release-gate.mjs` が実例。アカウント固有の値を外して取り込む)
- 公開に切り替えたあとの、利用者のログインと認可の検査。
- 公開後の、ロールバックの手順の自動化。
